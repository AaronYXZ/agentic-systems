State before autonomy

Your first LangGraph program has no LLM. That constraint makes the machinery visible: state enters, nodes return updates, and edges decide what runs next.

The central distinction
A workflow follows control flow you define. An agent lets a model dynamically choose some of that control flow. Both need observable state and explicit boundaries.

Read the graph

request
→
normalize
→
triage
answer
← specific · vague →
clarify
→
end

The graph state is a typed contract. Each node reads the current state and returns an update. The conditional edge reads route and selects the next node. No hidden control flow is required.

Prediction exercise

Without running the code, write the expected route, response, and audit_log for each input:

  1. Help
  2. Explain LangGraph state
  3.   design   a router  

Then run:

uv sync
uv run first-graph "Help"
uv run first-graph "Explain LangGraph state"
uv run first-graph "  design  a router  "
Check your model

Help names neither an accepted action nor an object, so it routes to clarification. The other requests start with the accepted actions explain and design and include meaningful objects, so they route to answer. Every audit log begins with normalize, continues with the route decision, and ends with the selected action.

Make one change

Add one justified action verb to the routing policy. Then add a test showing a request with that action and an object is accepted, while the action alone still asks for clarification.

Exit check

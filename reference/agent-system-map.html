Agent system map

A compact map of the layers in this course. Use it to avoid treating patterns, frameworks, and protocols as interchangeable.

One system, four layers

1. Reasoning and control patterns
ReAct alternates reasoning and action. A router chooses a branch. Reflection critiques or revises an output. Planning decomposes work before or during execution.
2. Runtime and application framework
LangChain supplies common model, message, tool, retrieval, and agent abstractions. LangGraph makes state transitions, branches, loops, persistence, and interruptions explicit.
3. Interoperability protocols
MCP standardizes how an AI application connects to tools and context. A2A standardizes how independent agents discover capabilities and collaborate on tasks.
4. Operational controls
Evaluations, traces, permissions, approval gates, timeouts, budgets, audit logs, and incident procedures make behavior governable.

State is not memory

TermPractical meaningTypical lifetime
StateData needed to execute the current graphOne run or thread
Short-term memoryConversation and working context retained across turnsOne thread
Long-term memorySelected information persisted and retrieved laterAcross threads
KnowledgeExternal source material retrieved for groundingIndependent of a user thread

MCP is not A2A

MCP equips an agent. Think agent-to-tool or application-to-context. A2A connects autonomous services. Think agent-to-agent discovery, delegation, task lifecycle, and artifacts.

Production questions

  • What decisions are deterministic, model-selected, or human-approved?
  • What state is persisted, for how long, and under whose identity?
  • Can every tool call be authorized, bounded, traced, and retried safely?
  • How do we detect unsupported claims and explain consequential outputs?
  • What happens on timeout, partial failure, duplicate delivery, or restart?
  • Does adding another agent improve measured quality enough to justify cost?
